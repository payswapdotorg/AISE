## Decision

The three geometry/BIM technology candidates evaluated by the wave-G0 spikes are **ADAPTED** — each strictly behind AISE provider/presentation boundaries, **never forked, never made an authority, never made a default provider**:

1. **Exact geometry kernel — OpenCASCADE Technology (OCCT) via OCP/CadQuery.** Adapted as the exact-solid lane behind a provider-neutral, process-isolated geometry port. Evidence: `docs/productization-evidence/GBIM-001/` (verdict: ADAPT — `GBIM-001/recommendation.md`).
2. **BIM/IFC interoperability — IfcOpenShell + IFC4** (Bonsai/Blender as desktop adapter). Adapted as an interop **projection** behind the Layer-3 provider boundary — IFC is never the storage or history authority. Evidence: `docs/productization-evidence/GBIM-002/` (verdict: ADAPT — `GBIM-002/RECOMMENDATION.md`).
3. **Browser spatial presentation — Three.js + web-ifc (That Open).** Adapted as a pure presentation adapter behind the browser presentation seam — the renderer holds no authority over quantities, validation or identity. Evidence: `docs/productization-evidence/GBIM-003/` (verdict: ADAPT — `GBIM-003/recommendation.md`).

This consolidates three parallel spike verdicts into one recorded architectural decision and closes the follow-through clause of the spike charter ("After G0, the Tech Lead decides whether to implement a provider adapter, create a shared geometry contract Work Item, stage an Architecture Change Record, or defer adoption" — `docs/geometry-bim-technology-spike-2026-09-25.md` §9) and of the roadmap ("A subsequent implementation recommendation must pass the technology-substitution contract, preserve AISE authority/provenance/uncertainty, and state whether the next action is adapter implementation, a new shared geometry contract Work Item, an Architecture Change Record, or deferment" — `docs/productization-roadmap.md` §Post-readiness geometry/BIM R&D).

**The stated next actions are: this Architecture Change Record + one new shared geometry-contract Work Item (DEFINED, not implemented — §"The shared geometry-contract Work Item") + explicit deferment of production implementation until a product requirement needs it (§"Deferment ledger").** Nothing is implemented, registered, promoted or replaced by this record.

The architecture law this decision operates under (charter §2, `docs/geometry-bim-technology-spike-2026-09-25.md`): provider output is never the Reality Graph or Solution Graph authority; provider-specific IDs, topology objects, file formats, scene graphs, mesh handles, IFC GUIDs and renderer object IDs are external references, not AISE semantic identity.

**Adapted (three lanes, one boundary law):**

**Not adapted, not forked, not defaulted:**

## The shared geometry-contract Work Item (DEFINED, not implemented)

GBIM-002's successor handoff named the follow-up: "one shared geometry-contract work item is the natural follow-up if all three wave-G0 spikes adapt" (`GBIM-002/RECOMMENDATION.md` §"Successor handoff" 5). All three adapted, so the Work Item is **defined** — its authoritative record is `docs/shared-geometry-contract-work-item-2026-09-30.md` (ID **GBIM-004 — the Shared Geometry Contract**), written in the work-order format of `docs/geometry-bim-spike-work-orders-2026-09-25.md` so a future worker can be dispatched against it directly. Summary of the definition (the docs/ record is authoritative):

- **Scope:** one typed, provider-neutral geometry port contract shared by the three adapted lanes — the zod-coded lift of the spike port (`GBIM-001/PORT.md` §2/§3) into `packages/` under the `solution-contract` codec discipline; the three port laws as typed, tested invariants; the AISE-side supervised subprocess runner (input digest, timeout, stdio JSON, output guard); the shared external-reference/mapping conventions (pset-pattern for the IFC lane, external-ref display rule + render-port formalization for the browser lane); and provider registration through the `packages/provider-registry` promotion gates. The contract's capability-profile decisions carry the GBIM-003 G-1/G-2 follow-ups (wall-thickness limits; opening host-existence + sill parameter slot) and the GBIM-001 D-5 validation-check decisions; it must declare interfaces for — not close — the deferred gaps (catalogue extension, G-3/G-4/G-5).
- **Dependencies:** the three spike evidence trees; `packages/solution-contract` codec discipline; `packages/provider-registry` control plane; the existing governed Layer-3 substitution surface (`backend/api/src/geometry-eval/`); the HFX-303 `visual-render` port pattern; the deferred AISE-side decisions as declared interfaces; a product requirement as the dispatch trigger.
